# MBD Canonical Direction

## Product promise

MBD should be the most trustworthy and legible long-save baseball dynasty simulator in the browser. Its edge is not more screens; it is complete, explainable loops that remain meaningful over decades.

## Four must-win loops

1. **Dynasty trust:** high-emotion action -> exact durable snapshot -> truthful save feedback -> reload proof.
2. **Prospect-to-legend:** origin -> commitment -> development/promotion -> debut/outcome -> permanent memory.
3. **Organization identity:** durable, fair preferences -> repeated choices -> recognizable reputation.
4. **Dynasty memory:** factual events -> deterministic links -> derived eras/rivalries -> honest old-save coverage.

## Non-negotiable guardrails

- Standing user authority removes permission-only pauses; it does not weaken
  any guardrail or gate (`STANDING_USER_AUTHORITY.md`).
- Source and tests outrank council documents.
- Determinism stays seeded and testable.
- No hidden CPU advantage.
- No fabricated old-save history.
- No schema change without complete migration proof.
- No mutation without explicit persistence ownership.
- No “Saved” before durable write completion.
- Extend existing routes before adding routes.
- Refactor only along the active slice boundary.
- No server-authoritative save redesign, service-worker mutation ownership, CRDT, or vector-clock sync for this local game.

## Release versus greatness

- **Any public release:** save trust, reload proof, old-save safety, deterministic gates, and green technical gates.
- **Product-defining release:** First Homegrown Star loop and a factual memory spine.
- **Long-save greatness:** CPU organization identity across decisions, era/rivalry storytelling, and calibrated multi-decade ecology.

All source-specific claims must be regenerated in the current worktree at the start of each goal.
